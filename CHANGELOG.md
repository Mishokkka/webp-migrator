# Changelog

## 0.4.8

- Исправлены 14 дефектов независимого аудита 0.4.7; регрессионные сценарии находятся в `tests/audit-regressions.test.mjs`.
- Обновления внутри массивов записывают целый сохранённый массив и проверяют соседние элементы; `flags` и Card faces больше не теряют данные из-за numeric dotted updates.
- Cleanup проверяет все пересекающиеся точные и wildcard-ссылки, учитывает пропущенные источники и отзывается при начале любого отката. Старые migration reports больше не разрешают очистку.
- Отмена возвращает частичный журнал выполненных изменений. HTML/text rollback использует проверяемые снимки текста, сохраняет разные исходные URL и уже существовавшие placeholder.
- PNG проверяется по CRC, zlib payload, размерам строк и декодированию; WEBP полностью декодируется `dwebp` при conversion/audit/cleanup. Некорректный payload не принимается по одному заголовку.
- `--dry-run` работает для cleanup и restore, включая сочетание с `--delete --permanent-delete`; несовместимые с режимом флаги отклоняются.
- Проверка после записи отвергает HTML, в котором осталась исходная PNG-ссылка. Простое текстовое описание с URL в конце больше не заменяется целиком.
- Report schema 5 требует полной файловой информации и Data-root binding. Отсутствующее свидетельство о файле означает unknown, а старый WEBP не авторизует автоматическое forward-repair.
- Убрано повторное URL-декодирование физических путей. Регистр определяется серверным отчётом; старые сгруппированные алиасы сохраняются при импорте.
- Полный CLI-тест использует реальные libwebp codecs на Windows и Linux; добавлены GitHub Actions для Node.js 20/24 и отдельная проверка модели установленного Foundry v13.

Подробнее о проверках и ограничениях: `AUDIT_FIXES_0.4.8.md`.

## 0.4.2

### Диагностика dry-run и удаленные ассеты

- Conversion dry-run теперь показывает конкретную причину `failed` прямо в UI, а не только общий статус.
- Проверка PNG сообщает, отсутствует ли файл, поврежден ли контейнер или файл с `.png`-путем фактически не имеет PNG-сигнатуры.
- PNG с безвредными хвостовыми байтами после `IEND` больше не отвергаются до запуска `cwebp`; полный файл по-прежнему хешируется для безопасного cleanup.
- Consistency audit выделяет отдельную категорию `repair-to-placeholder`, когда и PNG, и WEBP физически отсутствуют.
- В UI добавлена отдельная кнопка `Заменить отсутствующие на заглушку`, которая меняет такие ссылки на `icons/svg/mystery-man.svg`. Wildcard-пути не затрагиваются.
- Замена на заглушку проходит через те же stale-guards, Compendium/ActorDelta-safe writes и fresh verification, записывается в migration report и полностью поддерживает rollback.
- Замена на заглушку никогда не дает cleanup-разрешения и отзывает старое cleanup-разрешение для затронутого пути при объединении отчетов.

## 0.4.1

### Исправления consistency repair и Compendium embedded documents

- Embedded documents больше не обновляются прямым `document.update()`: запись выполняется через `parent.updateEmbeddedDocuments(...)`, что корректно сохраняет Tile, Token и другие вложенные документы внутри Compendium.
- `ActorDelta` внутри Token исправляется через `Scene.updateEmbeddedDocuments("Token", [{_id, "delta.…": value}])`, как рекомендует Foundry для миграций Token delta. Это устраняет ошибки `Cannot read properties of undefined (reading 'id')` на старых Compendium Scenes.
- После любой записи Compendium root перечитывается через `pack.getDocuments({_id__in: [...]})`, и проверка выполняется по свежему дереву документов, а не по устаревшему embedded instance в памяти.
- Если Foundry выбросил исключение после фактически состоявшейся записи, свежая проверка признаёт изменение успешным и сохраняет его в `changedRefs`, поэтому возможность rollback не теряется.
- Старые/частичные manifest refs с некорректным `rootUuid` безопасно восстанавливают root из полного UUID документа.
- Исправлена запись CLI-отчётов непосредственно в корень диска Windows: существующий `D:\` больше не передаётся в `mkdirSync`, что устраняет `EPERM: operation not permitted, mkdir 'D:\'`.
- Добавлены regression tests для Compendium Tile, Compendium Token → ActorDelta, свежей post-write verification и сценария «запись состоялась, затем hook выбросил ошибку».

## 0.4.0

### Исправления ревью PR #2

- Исправлена обработка `.webp`-имен с буквальными `?` и `#`.
- Ссылки, объединенные по регистру пути, сохраняют собственное написание пути и корректно проходят импорт manifest.
- Consistency audit теперь отклоняет отсутствующий и нечисловой `schemaVersion`.
- Отсутствующая базовая папка wildcard трактуется как отсутствие совпадений, а не как ошибка операции.
- Частичный rollback сохраняет отчеты для повторной попытки; API публикуется даже при сбое восстановления блокировок compendium.
- Сводка объединенных migration reports полностью пересчитывается, а поздний частичный результат отзывает устаревшее cleanup-разрешение.
- Добавлены regression tests отмены, частичного rollback, регистровых алиасов, schema gate и отсутствующих wildcard-папок.

### Проверка согласованности

- Сканер теперь собирает как PNG-, так и WEBP-ссылки и сохраняет их в раздельных разделах manifest.
- Добавлен внешний режим `--audit`, который ничего не меняет на диске и проверяет обе стороны каждой PNG/WEBP-пары.
- Audit report содержит структурную проверку изображений, размеры, SHA-256, размер файла, mtime и отдельные результаты для каждого конкретного wildcard-файла.
- Добавлена безопасная автоматическая коррекция `PNG -> WEBP`, когда корректный WEBP подтвержден на диске.
- Добавлена безопасная автоматическая коррекция `WEBP -> PNG`, когда WEBP отсутствует или поврежден, а корректный PNG сохранился.
- APNG, несовпадающие размеры, частично небезопасные wildcard-пары, отсутствующие или поврежденные обе стороны остаются без изменений.
- Foundry повторно вычисляет разрешения из файловых данных отчета и не доверяет готовым статусам или сводке импортированного JSON.
- Manifest 0.3.x не может использоваться для consistency audit, поскольку не содержит полного сканирования WEBP-ссылок.
- Исправление согласованности не создает cleanup-разрешений и никогда не удаляет файлы.

### Откат и объединение отчетов

- Migration report хранит направление каждого изменения и поддерживает откат как `PNG -> WEBP`, так и `WEBP -> PNG`.
- Противоположные последовательные изменения одного поля взаимно отменяются в объединенной истории отката.
- Возврат пути на PNG отзывает прежнее разрешение отправить этот PNG в cleanup.
- Cleanup-списки сохраняются при объединении отчетов с тем же Data root. При конфликте Data-root fingerprint cleanup-разрешения отбрасываются.

### UI и API

- Добавлена отдельная панель проверки согласованности, импорт consistency report, сводка, preview и список неоднозначных случаев.
- Manifest summary показывает количество найденных PNG- и WEBP-ссылок.
- Публичный API получил метод `auditRepair`.
- README переписан и разделяет восстановление уже рассинхронизированного мира, новую конвертацию и cleanup.

### Тесты

- Добавлены тесты WEBP scanner, consistency CLI, двусторонней коррекции, повторного вычисления разрешений, двустороннего rollback и безопасного объединения cleanup-отчетов.

## 0.3.0

### Безопасность и целостность данных

- Исправлена тихая no-op миграция путей с хвостовыми пробелами, которая могла разрешить cleanup при оставшейся PNG-ссылке.
- Текстовые замены ограничены границами токена и больше не меняют совпадающий суффикс внутри другого пути.
- Импортируемые manifest references проверяются по `oldValue`, `newValue`, `oldPath` и `newPath`; измененный manifest не может перенаправить запись на произвольное значение.
- `applyMigration` самостоятельно проверяет `manifestId` и `worldId` перед любыми изменениями.
- Непроверенный режим `WEBP уже готовы` защищен внутренним непереносимым маркером и никогда не дает права на cleanup.
- Conversion report полностью санитизируется: удаляются опасные ключи, пересчитываются статусы, сводки и допустимые файловые метаданные.
- Документы обновляются leaf-полями вместо записи целого корневого объекта, что предотвращает затирку параллельных изменений соседних полей.
- После update допускается безопасная нормализация значения системой при сохранении того же физического WEBP-пути.
- Повторные применения объединяют историю отката; migration report можно импортировать после перезагрузки Foundry.
- Запланированное восстановление блокировок world compendiums хранится в world setting и выполняется при следующем запуске после аварийного прерывания.
- Unknown package types больше не трактуются как package compendiums.

### Внешний конвертер и cleanup

- Переписан CLI parser: неизвестные и дублирующиеся флаги отклоняются, boolean-флаги не принимают значения. `--delete false` больше не включает удаление.
- Исправлена обработка wildcard `?` и буквального `#` в именах файлов.
- APNG проверяется до ветки существующего WEBP и всегда пропускается.
- PNG и WEBP проходят структурный разбор. Укороченный RIFF-заголовок и VP8X-контейнер без image chunk больше не считаются изображением.
- Все файловые дескрипторы закрываются через `finally`.
- Добавлены SHA-256, размеры, dimensions, mtime и provenance для каждого конкретного файла.
- Существующий WEBP проверяется по dimensions и времени; старый WEBP требует `--trust-existing`.
- WEBP больше PNG получает `larger` и не разрешает миграцию без `--allow-larger`.
- `--overwrite` использует временный файл и сохраняет прежний WEBP при любой ошибке проверки.
- Добавлена защита от выхода через symlink/junction за пределы Data.
- Добавлена привязка команд к `--world-id` и Data-root fingerprint.
- Wildcard directories кешируются при конвертации.
- Cleanup больше не разворачивает wildcard по текущему состоянию папки. Используются только конкретные `cleanupFiles` из migration report.
- Cleanup повторно сверяет старый и новый SHA-256, размеры и dimensions.
- `--delete` теперь перемещает PNG в карантин. Безвозвратное удаление требует `--delete --permanent-delete`.
- Добавлен режим `--restore` с проверкой хеша.
- Добавлен conversion `--dry-run`.
- Абсолютные локальные пути не попадают в отчеты без `--include-local-paths`.

### Сканирование и UX

- `scanFoundry` санитизирует options на собственной публичной границе.
- Compendium packs обрабатываются последовательно, без накопления документов всех паков одновременно.
- Bare filenames обнаруживаются в rich text, известных asset-полях и массивах.
- Нормализуются `.`-сегменты; UNC, absolute и drive-relative пути отклоняются.
- На Windows/macOS объединяются алиасы путей, различающиеся только регистром.
- Chat Messages явно помечены как покрывающие только загруженную историю.
- Закрытие confirm через X/Esc считается отменой, а не ошибкой.
- Статус длинных операций обновляется во время работы; добавлена кнопка остановки.
- В UI отображаются конкретные проблемы manifest, conversion, migration и rollback, а также счетчик обрезанного preview.
- Добавлены подтверждение reset и дополнительное предупреждение перед записью в package compendiums.
- Подсказка package writes уточняет, что module/system packs автоматически не разблокируются.
- Cleanup-команды используют точные экспортируемые имена файлов и `--world-id`.
- Добавлены русская и английская локализации.
- Публичный API доступен также через `game.modules.get("fbl-webp-migrator").api`.

### Разработка

- Требуется Node.js 20 или новее.
- `npm run check` теперь запускает все тесты и отдельно проверяет синтаксис `tools/convert-cwebp.js` и `scripts/main.mjs`.
- Добавлены функциональные CLI-тесты conversion, wildcard, APNG, WebP validation, symlink escape, overwrite, cleanup, quarantine и restore.
