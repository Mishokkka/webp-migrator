# FBL WebP Migrator 0.4.0: проверка согласованности

## Закрываемая проблема

Версия 0.4.0 добавляет отдельный восстановительный процесс для двух классов рассинхронизации:

1. Foundry хранит путь `.webp`, но WEBP отсутствует или поврежден, тогда как исходный PNG сохранился.
2. Foundry хранит путь `.png`, хотя корректный WEBP уже существует.

## Новый поток

1. Foundry сканирует выбранные документы и собирает обе категории ссылок.
2. Manifest экспортируется с `entries` для PNG и `webpEntries` для WEBP.
3. `tools/convert-cwebp.js --audit` проверяет реальные файлы в `Data` и создает consistency report.
4. Foundry повторно санитизирует отчет и самостоятельно пересчитывает разрешенные направления.
5. Кнопка `Исправить безопасные случаи` меняет только подтвержденные leaf-поля.
6. Migration report сохраняет направление каждого изменения и поддерживает двусторонний откат.

## Матрица автоматических решений

| Текущий путь Foundry | PNG | WEBP | Решение |
|---|---|---|---|
| PNG | отсутствует или поврежден | корректен | заменить путь на WEBP |
| PNG | корректен, не APNG | корректен, размеры совпадают | заменить путь на WEBP |
| WEBP | корректен | отсутствует или поврежден | вернуть путь на PNG |
| PNG или WEBP | оба отсутствуют | оба отсутствуют | не менять |
| PNG или WEBP | оба повреждены | оба повреждены | не менять |
| PNG | APNG | любой WEBP | не менять |
| PNG или WEBP | корректен | корректен | не менять (размеры различаются) |
| wildcard | хотя бы один конкретный файл небезопасен | смешанное состояние | не менять всю пару |

## Защита данных

- Audit не конвертирует, не перемещает и не удаляет файлы.
- Consistency repair не создает `cleanupFiles`.
- Требуется manifest schema 4 с явным маркером полного WEBP-сканирования.
- Consistency report должен совпадать по `manifestId`, `worldId` и содержать Data-root fingerprint.
- Разрешения не берутся из готовых полей JSON. Они пересчитываются по санитизированным сведениям каждого файла.
- Для корректного файла требуются полные доказательные поля: структура изображения, dimensions, SHA-256, размер и mtime.
- Перед записью действует stale guard.
- Изменяются leaf-поля, после `Document.update` результат проверяется повторно.
- Возврат ссылки на PNG отзывает ранее накопленное cleanup-разрешение для всей пары.
- Противоположные последовательные изменения одного поля отменяются в объединенной истории отката.

## Проверка

`npm run check` проходит 46 тестов. Новые тесты покрывают:

- поиск WEBP-ссылок в точных полях, массивах и rich text;
- экспорт WEBP-части manifest;
- CLI audit и его Data/world binding;
- отказ для старого manifest;
- повторное вычисление разрешений после импорта;
- запрет изменения при неполных файловых метаданных;
- двустороннее исправление и двусторонний rollback;
- отмену взаимно противоположных изменений;
- отзыв cleanup после возврата на PNG;
- отказ от cleanup при конфликте Data roots;
- объединение дублирующихся импортированных manifest entries.

Живой smoke test внутри Foundry VTT 13.351 в этой среде не выполнялся.


## Дополнение 0.4.2: отсутствуют оба файла

Если audit подтверждает, что для конкретного не-wildcard пути отсутствуют и PNG, и WEBP, путь получает статус `repair-to-placeholder`. Отдельная UI-команда заменяет все найденные ссылки на `icons/svg/mystery-man.svg`. Операция не удаляет файлов, не выдает cleanup-разрешений и поддерживает rollback через migration report.
