18 октября 2026. Основа изменений — `main` после объединения PR #6, commit `d646c281760eae5504147bce294c4f134f08a376`.

| Дефект аудита | Изменение и проверка |
|---|---|
| A01. Потеря элементов и свойств массивов | Запись ближайшего массива целиком с объединением всех изменений и проверкой его сохранённого содержимого. Проверены вложенные массивы, flags и faces; отдельно — настоящий Foundry DataModel. |
| A02. Cleanup при необработанной пересекающейся ссылке | Проверка всех точных и wildcard-ссылок на конкретный файл. Неподтверждённые conversion entries тоже отзывают прежнее разрешение при merge. Пропущенные scan sources блокируют cleanup. |
| A03. Cleanup после частичного rollback | Разрешение отзывается до первой записи, в UI, core recovery и mutation API. Обновлённый отчёт с `cleanupRevoked` не принимается CLI для очистки. |
| A04. Принятие повреждённого payload | Полное декодирование WEBP через dwebp; для PNG — CRC, zlib, длина и фильтры строк плюс декодирование cwebp. Header-only VP8L отвергается при conversion, audit и cleanup. |
| A05. Потеря истории при отмене | Возвращается частичный отчёт с выполненными изменениями и признаком cancelled. Отмена проверяется между документами; текущая запись дочитывается и проверяется. |
| A06. Коллизии placeholder при откате текста | Журнал исходного/итогового текста и валидируемых операций. Разные URL и существовавший SVG восстанавливаются точно. Merge, повторный частичный rollback и stale после пользовательской правки покрыты тестами. |
| A07. Игнорирование dry-run | CLI cleanup и restore не двигают файлы при `--dry-run`; это проверено запуском настоящего CLI, включая `--delete --permanent-delete --dry-run`. |
| A08. Успешная верификация при оставшемся PNG | Наличие нового URL недостаточно: исходный URL тоже должен исчезнуть. Неподтверждённые записи сохраняются в unverifiedWrites и не разрешают cleanup. |
| A09. Замена целого текстового описания | Текст, заканчивающийся URL, распознаётся как text reference. Проверено сохранение префикса описания и обратное восстановление. Заодно исключены ложные ссылки на хвосты имён с пробелами внутри HTML-атрибутов. |
| A10. Verified при неполных метаданных | Schema 5, Data-root ID, хеши, размеры, mtime, совпадение dimensions и подтверждение декодирования обязательны. Некорректный concrete child не отбрасывается с сохранением успешного статуса остальных. |
| A11. Неизвестное состояние превращалось в missing | Отсутствующее/неверное exists становится unknown. Placeholder возможен только при явном exists=false с обеих сторон. Неполные сведения о проверенном файле не разрешают repair. |
| A12. Старый WEBP разрешал forward-repair | Совпадения dimensions недостаточно: WEBP не должен быть старее валидного PNG. Ограничение действует и в CLI, и при импорте. |
| A13. Разные правила регистра CLI и браузера | CLI записывает caseInsensitivePaths; importer использует его. Сканер сохраняет каждое написание пути. При импорте старых сгруппированных manifest ни один допустимый alias не теряется. |
| A14. Повторное percent-decoding | URL декодируется при извлечении ссылки, физические пути manifest/report/CLI больше не декодируются. Полный roundtrip проверен для URL `%2520` → файла с буквальным `%20`. |

## Совместимость и границы

Версия модуля и CLI — 0.4.8; manifest остаётся schema 4, отчёты переходят на schema 5. Conversion/consistency reports старых версий нужно создать заново. Cleanup требует новый migration report. Старые migration reports сохраняют возможность отката точных ссылок; автоматический откат text references без исходного снимка запрещён, потому что нельзя отличить заменённые вхождения от существовавших до миграции.

`cwebp` и `dwebp` требуются для conversion, audit и cleanup, в том числе dry-run. `dwebp` ищется рядом с явно указанным cwebp либо в PATH; предусмотрен `--dwebp`. Restore по-прежнему работает по хешам. PNG validation ограничена 512 MiB распакованных данных и 512 MiB на chunk; превышение безопасно прекращает проверку.

Новый журнал защищает отмену через API/кнопку и точный откат текстовых полей. Это не транзакционный журнал на сервере: закрытие вкладки или авария до экспорта отчёта остаются отдельным риском. Поля и массивы следует мигрировать без одновременного редактирования другими клиентами.

Cleanup знает только ссылки из выбранных областей сканирования. Ранее экспортированный JSON невозможно автоматически отозвать после последующих изменений мира или rollback; использовать его снова нельзя. Для очистки нужен актуальный отчёт. Размеры и mtime существующего WEBP не являются доказательством визуальной идентичности исходнику.
